## The `scope` escape finding — recorded, then disproven PER CLASS (never waived)

`check-regress.mjs scope` exited **1** naming **14** escapes. That number is large enough to be worth
explaining rather than dismissing, and the explanation is structural, not exculpatory.

**Why so many.** `scope` asks **changed-since-base**, and the base is the last **commit**. This working
tree carries **two** increments — `out-of-root-deny-message` and this one — neither committed yet, plus
the two lesson promotions that came out of the first one's review. `--feature plan-cue-continuation`
exempts only **this** feature's own artifacts, so everything belonging to the first increment appears here
as an undeclared change. `.dev/memory-bank/lessons-learned.md` **L17** names exactly this shape.

Four classes, each disproven on its own evidence:

1. **`.claude/hooks/set-writes-scope.cjs` and `.claude/hooks/enforce-writes-scope.cjs`** — both
   human-applied. `protect-trusted-paths.cjs` (fix #2) denies `Write`, `Edit` and `MultiEdit` on each, and
   both files are on `set-writes-scope.cjs`'s own `CONTROL_SURFACE`. No agent write could have produced
   them. Each matches, byte for byte, the worktree copy that `npm run check` passed at exit 0 —
   `a2bd0203…` for the setter, `396ea124…` for the enforcer.
2. **`.dev/features/out-of-root-deny-message/**`** — the previous increment's artifacts. Each was written
   by its own stage under that stage's own Step-0 writes-scope, and each is declared in **that**
   increment's plan. They are undeclared _here_ only because they belong to a different plan.
3. **`.dev/memory-bank/lessons-learned.md`** — the two gated promotions (L27, L28).
   `check-provenance.mjs` returned GREEN on each candidate, and the fix #7 scope was pinned to that single
   canon file for the write. This is the one path in the repo whose write is _supposed_ to be conspicuous.
4. **`docs/lessons-index.md`** — the derived index, regenerated by `npm run docs:generate` after the
   promotions. A Bash write, therefore outside the `PreToolUse` gate (**L19**), and declared as such rather
   than pretended to be covered. `npm run docs:check` is GREEN, which is the guarantee that actually
   applies to it: byte-equality with canon, never truth.

**A named limitation, not a clean bill of health.** Stacking two increments in one uncommitted working
tree makes this partition structurally noisy: `scope` cannot use "after increment 1" as a base until
increment 1 is a commit. The disproof above is conclusive for these 14 paths, but the mechanism that
produced 14 would produce more with every additional stacked increment, and at some count "recorded, then
disproven" stops being read carefully — which is the failure mode L17 exists to prevent. **The remedy is
to commit each increment before starting the next**, and that is what the pull request does.
