## Guarantee audit (P0)

- "every `enforces` rule_id is produced by ≥1 eval fixture" → **FLOOR**: enum/regex (primitive #3) —
  exact set membership of the declared id (or its bare form) in the set of `rule_id` VALUES read from
  the fixtures' structured location. This is the same primitive as before; the increment removes a
  false-GREEN class from it, it does not add a primitive.
- "a rule_id appearing only in fixture free text satisfies the binding" → **STRUCK**. It did (live,
  reproduced); after this increment it does not, because free-text strings (`semantic[].judge`,
  `needle`, prose) are never read into the produced-set.
- "the binding proves the eval genuinely EXERCISES the rule" → **NOT a guarantee, advisory.** The floor
  proves a fixture DECLARES that value at the structured location. Whether the case actually elicits
  that finding from a live capability is `/pharn-dev-eval`'s measurement problem (L4), not this check's.
  Do not write "the rule is tested"; write "the rule id is declared by ≥1 expected fixture".
- "an unparseable expected fixture cannot silently weaken the binding" → **FLOOR**: the parse failure is
  itself a blocking finding, so the fixture can no longer fall through to `""`.
- "CHECK 3's scope" → unchanged and NARROW, stated: it fires only for capabilities that declare a
  non-empty `enforces`. A capability with no `enforces` gains no new failure mode from this increment,
  including the new malformed-fixture RED (P7 — no blast radius beyond the triggering defect).

## Trust audit (P2)

- `evals/expected/*` is `trust: trusted` per `eval-format.md`; `evals/cases/*` is untrusted and is NOT
  read by CHECK 3. Extracted `rule_id` values are used ONLY as string operands in a Set equality
  compare — never executed, never spawned, never routed anywhere.
- The produced-set is built exclusively from enum-gated positions (`field_equals` `value` where `field`
  is `rule_id`, or an anchored `rule_id:` line). Free-text positions (`judge`, `needle`, `purpose`,
  prose) are structurally excluded — so no gate decision can rest on a tainted field, which is the same
  taint boundary `check-structural.mjs` already holds.
- One free-text egress, named rather than hidden: a `JSON.parse` failure message may quote a short
  snippet of fixture bytes into the finding's `problem`. `problem` is the free-text/untrusted half of
  the finding-shape split (fix #1), is rendered as quoted DATA in validate's report, and is read by no
  gate — the identical posture `pharn/floor/check-structural.mjs` already takes for its `input` reds.

## Determinism audit (P5)

- Every branch is a membership/equality test: fixture kind by `.json` suffix; assertion selection by
  `kind === "field_equals" && field === "rule_id"`; binding by `Set.has(id) || Set.has(bare)`.
- No fallback chain ends in a guess. An unreadable file, an unparseable JSON, or an unrecognised
  fixture shape yields a loud blocking finding (fail-closed) — the terminal state is a RED a human
  reads, never a silent pass.
- Object access on parsed fixture data uses shape checks on own properties and `Array.isArray` guards
  before iteration (L15's family), so a fixture shaped `{"assertions": {"structural": "x"}}` REDs the
  binding rather than throwing.
