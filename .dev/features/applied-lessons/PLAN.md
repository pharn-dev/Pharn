## The checker (exact semantics — R3)

`node pharn/floor/check-plan-lessons.mjs <PLAN.md> <lessons-learned.md>` → exit 0 GREEN / 1 RED,
message style `RED — <msg>`, stdlib-only, zero `.claude/` strings, zero harness names.

**Field extraction (structured only — L6).** Frontmatter via the `FM_RE` precedent re-implemented
in-file (P3 — no sibling import); if the file has no frontmatter, read the **leading bullet block**
(`- key: value` lines up to the first `##`). Strip a trailing `# comment` and surrounding quotes, as
the existing header fields already carry (`- spec_content_hash: <hash> # fix #4`).

**Value grammar (floor primitive #3 — enum/regex).** `none` **or** `[L<n>]` / `[L<n>, L<m>, …]`.

| condition                                              | verdict                            |
| ------------------------------------------------------ | ---------------------------------- |
| field absent from the structured header                | **RED** (omission ≠ escape)        |
| value neither `none` nor a well-formed `L<n>` list     | **RED**                            |
| a cited `L<n>` has no `## L<n>` heading in the lessons | **RED**, naming the id             |
| non-empty list + lessons file missing/unreadable       | **RED**                            |
| `none`                                                 | **GREEN**, lessons file irrelevant |

`none` is GREEN regardless of the lessons file because a product project may legitimately have no
memory-bank yet — `none` plus a one-line note is the honest state, not a gap.

**Grill resolutions (post-approval, from `GRILL.md` F1/F2/F4 — under-specifications, not scope changes).**

- **`[]` → RED**, fail-closed, with a message naming `none` as the intended escape. `[]` and `none` read
  as the same thing to a human, but only `none` was designed as the deliberate declaration; admitting
  `[]` would create a quieter second spelling and reopen the silent omission this increment closes.
- **Carrier precedence:** search the `---`-fenced frontmatter **first**; if the field is not there,
  search the **leading bullet block** (the region before the first `##`). Both are structured header
  regions, so this needs no fragile "does this file have frontmatter" branch and handles both plan
  shapes uniformly. Prose and fenced blocks are never searched (L6).
- **Lexical:** `L` is **case-sensitive** (`[l1]` → RED, fail-closed); inner whitespace is tolerated
  (`[ L1 , L2 ]`); duplicates are tolerated and de-duplicated before the existence check.

## Trust audit (P2)

- **Input.** `PLAN.md` and `lessons-learned.md` are untrusted DATA. The verdict ranges **only** over the
  enum-gated `applied_lessons` value (regex-gated to `none`/`L<n>` **before** any use) and heading
  membership — **never** over either file's prose. A needle in a lesson body or plan prose cannot move
  the verdict; a needle **in** the field is rejected as not-matching-the-grammar.
- **Output.** The GREEN/RED line is a deterministic verdict, not model text.

## Determinism audit (P5)

- Every branch is a membership test: regex match on the value, set membership on `## L<n>` headings,
  exit-code branch in the commands. No LLM classification anywhere in the checker.
- Terminal fallback: RED with an actionable message naming the offending field/id — never a guess. The
  product lessons **path** was **asked, not invented** (Q1 → root `memory-bank/lessons-learned.md`).

## BLOCKING PRE-BUILD STEP (from Q3) — re-pin the spec hash — ✅ DONE

The `spec_content_hash` in this plan's header pins `pharn/ARCHITECTURE.md` as it stood at planning time
(`0d0dc6da…`, commit `de83cbb`). The human's §6 edit **changes that file's bytes**, so the pin goes
**stale** and `/pharn-dev-build` will correctly **REFUSE** the plan (fix #4 — drift is detectable, not
silent). The required order is therefore:

1. **Human** edits `pharn/ARCHITECTURE.md §6` — adds `applied_lessons` to the plan-artifact row.
2. **Re-pin**: recompute `sha256(pharn/ARCHITECTURE.md)` and replace this plan's `spec_content_hash`.
3. **Then** `/pharn-dev-build` runs.

This is fix #4 working exactly as designed, not a defect: the refusal is the guarantee. The re-pin is a
**deterministic** recompute of a hash (primitive #2), never a judgment — and it is the _only_ plan edit
the §6 change requires, since nothing else in this plan depends on §6's wording.
